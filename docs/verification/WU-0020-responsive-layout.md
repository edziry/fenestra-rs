## Implemented result

The public facade and both format-3 frontends now support fixed, intrinsic
and weighted dimensions with minimum/maximum bounds. Existing numeric syntax
keeps its canonical output. The [design](../design/responsive-layout.md)
defines deterministic allocation, overflow and measurement behavior.

The facade resolves widths before wrapped text heights, then submits fixed
dimensions to the existing runtime and spatial resolver. A viewport resize,
text edit or typography update can move subsequent siblings without an
application callback calculating geometry. Content, authored styles, resolved
dimensions, metrics, pixels, hit targets and generation publish together.
Rejected measurement, text raster budgets or runtime geometry preserve the
previous accepted application state.

Text engines can measure without allocating an output raster. Existing
layout-only engines remain usable for fixed boxes and explicitly report
unsupported intrinsic measurement. Natural and current-width measurements
are cached alongside the current raster. Content and typography invalidate
those caches; identical inputs remain no-ops. Measurement and raster metrics
at the same width must agree before publication.

The [standalone responsive consumer](../../examples/responsive-app/README.md)
combines a fixed sidebar, flexible reading column, automatic text heights and
bounded weighted cards. Its only runtime dependencies are the public facade
and explicit-font adapter. Its handler changes authored state on clicks;
the shared native host handles viewport resize.

## Regression evidence

- [Solver tests](../../crates/fenestra-ui/src/layout/tests.rs) and their
  [distribution](../../crates/fenestra-ui/src/layout/tests/distribution.rs)
  and [measurement](../../crates/fenestra-ui/src/layout/tests/measurement.rs)
  modules cover both axes, minima, capped redistribution, integer remainders,
  zero width, intrinsic fill contributions and final-width measurement.
  New solver cases failed before implementation. Two aggregate-size cases
  separately reproduced premature signed overflow before its fix: intrinsic
  sums now apply min/max bounds before narrowing their final dimensions.
- [Public responsive tests](../../crates/fenestra-ui/tests/responsive.rs)
  preserve authored policies even when their current pixels agree, verify
  no-ops, and resize twenty fill siblings in one generation. Runtime operation
  capacity now scales with node count rather than a fixed sixteen operations.
- [Reflow tests](../../crates/fenestra-ui/tests/responsive_text.rs) verify
  moved sibling paint and hits, retained old rasters, text/style updates,
  measurement reuse and aggregate area rejection before new raster work.
  [Failure tests](../../crates/fenestra-ui/tests/responsive_measurement.rs)
  reject invalid metrics, unsupported measurement and inconsistent raster
  output while retaining accepted state and allowing retry.
- [Measurement contract tests](../../crates/fenestra-ui/tests/text_measurement.rs)
  and [adapter tests](../../crates/fenestra-ui-text/tests/measurement.rs)
  cover optional zero width, checked numeric bounds, glyph limits, hard breaks,
  mixed-direction content and exact same-width measurement/layout agreement.
- [Authoring tests](../../crates/fenestra-ui-authoring/tests/view_dimensions.rs)
  verify canonical fixed-output compatibility, equivalent frontends and
  source-located invalid policies, bounds and weights. The external consumer
  independently compiles both `.fen` and the real `ui!` macro.

## Remaining scope

This implements bounded row/column sizing, not CSS flexbox conformance.
General alignment, shrinking, container wrapping, grid, scrolling, focusable
controls and practical authored component/state binding remain open.
Text area limits still bound logical raster area rather than total heap;
private shaping work and retained image copies need separate performance and
memory qualification. The explicit-font admission is unchanged.

Windows cross-compilation remains build evidence. Current Windows responsive
presentation, X11, scale behavior, accessible controls and native IME are not
qualified by this increment. The [completion goal](../project-completion-goal.md)
remains active while mandatory product gates are outstanding.
