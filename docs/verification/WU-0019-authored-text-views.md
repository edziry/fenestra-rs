## Implemented result

Format 3 now compiles fixed-size `text` leaves from `.fen` and `ui!`, including
cooked/raw Rust strings, Unicode content and source-located failures. Content
and typography lower to owned public constructors. The earlier format-1/2
IR, source maps, generated artifacts and diagnostic contracts remain intact.

The facade exposes `TextEngine`, validated requests/layouts, complete metrics,
typed styles/errors and aggregate text budgets. Named text updates, typography,
dimensions, paint and runtime generation publish together. No-op updates skip
shaping and keep generation; translation reuses accepted text layouts. Failed
shaping, invalid adapter output, resource limits or runtime layout retain the
previous content, metrics, geometry and pixels. Zero-area text retains content
but has no shaped layout or image until its box grows.

The new [adapter](../../crates/fenestra-ui-text/src/lib.rs) supplies explicit
ordered font fallback through Parley 0.11.1 and Swash 0.2.6. Font registration
is bounded and excludes host discovery, collections and color/bitmap fonts.
Missing coverage is a typed failure. Candidate types remain private, and the
default facade graph does not include this optional consumer dependency.

The [standalone text application](../../examples/text-app/README.md) compiles
both frontends and uses only public application APIs. It demonstrates real
multilingual text, content/style updates, basic end-of-buffer editing, IME
event handling, headless execution, native smoke and explicit PPM export.

## Exact bounded raster improvement

For integer solid rectangles and one-to-one integer image mappings, every
registered sample within a pixel has identical coverage/color. The reference
raster now checks this condition once per frame and uses one center sample
when all accepted transforms, bounds and clips preserve it. Other frames use
the original sixteen samples. Ordered source-over and image sampling are shared.

Eleven [equivalence/fallback tests](../../crates/fenestra-ui-spatial/src/input_validation/tests/prepared_spatial_contract/raster_pixel_constant.rs)
cover overlapping alpha, images, negative placement, ancestor clips, scalar
edges and unsupported geometry/transform cases. The entire preexisting spatial
suite passed, including frozen raster evidence.

A focused release comparison at 320 by 180 pixels with three solid rectangles
and one 160 by 40 premultiplied image measured 80.147097 ms for the original
samples and 4.930553 ms for the constant-sample path, with exact byte equality.
This is a local diagnostic observation, not a framework latency budget or a
general speedup claim for fractional geometry, GPU rendering or arbitrary apps.

## Limits and next work

The [design](../design/authored-text-views.md) defines fixed text boxes, complete
unclipped metrics, strict missing coverage and explicit fonts. Intrinsic sizing,
wrapping driven by flexible container layout, normal focusable text controls,
selection/caret geometry, clipboard, undo, visual bidi navigation, scrolling,
accessibility and native IME candidate placement remain required work.

Text pixel budgets bound logical bitmap area, not total heap use. The facade
retains layout pixels and an owned image copy; each effective commit rebuilds
the augmented frame even when shaping is reused. Candidate parsing and outline
decomposition still allocate before output limits are checked. Arbitrary font
hardening, broad font/script evidence, production cache budgets, startup/input
latency and an executed MSRV lane remain unqualified.

Windows cross-compilation is build evidence only. Current Windows text execution,
Linux X11, native scale/IME/accessibility behavior and GPU text are not qualified
by this increment. The separate earlier Windows GPU evidence is unchanged.
The [completion goal](../project-completion-goal.md) remains active.
